# 🔌 Pocket Mentor — API Specification

This document details the REST API endpoints provided by the Pocket Mentor Node.js/Express backend.

**Base URL**: `http://localhost:5000/api` (or environment-configured `PORT`)  
**Protocol**: HTTP/1.1 or HTTPS  
**Content-Type**: `application/json`

---

## 1. Endpoints Overview

| Method | Endpoint | Description | Auth Required |
| :--- | :--- | :--- | :--- |
| `GET` | `/health` | Healthcheck and service availability probe | No |
| `POST` | `/generate` | Primary endpoint: ingests notes and returns summary, flashcards, and quiz | No |
| `POST` | `/sessions` | *(Optional)* Save completed session results and score to MongoDB | No |
| `GET` | `/sessions` | *(Optional)* Retrieve recent revision session history | No |

---

## 2. Endpoint Details

### 2.1 Healthcheck

#### `GET /health`
Returns the operational status of the server and LLM integration.

- **Request**: No parameters or body.
- **Success Response** (`200 OK`):
  ```json
  {
    "status": "ok",
    "timestamp": "2026-09-10T05:00:00.000Z",
    "llmConfigured": true
  }
  ```

---

### 2.2 Generate Revision Materials

#### `POST /generate`
Accepts raw lecture notes and requests the LLM to return structured summary, flashcard, and quiz data.

- **Headers**:
  - `Content-Type: application/json`

- **Request Body**:
  ```json
  {
    "notes": "Operating Systems lecture: Paging is a memory management scheme that eliminates the need for contiguous allocation of physical memory. Pages are fixed-sized blocks of virtual memory, and frames are fixed-sized blocks of physical memory. The Page Table translates virtual addresses into physical addresses. Page Fault happens when a program accesses a page not currently mapped in RAM.",
    "mode": "fresh"
  }
  ```
  - `notes` *(string, required)*: The text content of the lecture notes (minimum 20 characters, maximum 15,000 characters).
  - `mode` *(string, optional)*: `"fresh"` (default) or `"variation"` (used when clicking *Revise Again* to prompt for different quiz questions).

- **Success Response** (`200 OK`):
  ```json
  {
    "success": true,
    "data": {
      "summary": "Paging is a memory management technique that avoids contiguous memory allocation by dividing virtual memory into fixed-size blocks called pages and physical memory into frames. A Page Table maps pages to frames to translate addresses. When a required page is not in physical RAM, a Page Fault is triggered, causing the operating system to retrieve it from disk storage.",
      "flashcards": [
        {
          "question": "What is the primary difference between a Page and a Frame?",
          "answer": "A Page is a fixed-sized block of virtual memory, whereas a Frame is a fixed-sized block of physical memory (RAM)."
        },
        {
          "question": "What is the purpose of a Page Table?",
          "answer": "It translates virtual addresses generated by the CPU into physical addresses in RAM."
        },
        {
          "question": "What triggers a Page Fault?",
          "answer": "A Page Fault occurs when a program attempts to access a virtual memory page that is not currently loaded into physical RAM."
        }
      ],
      "quiz": [
        {
          "question": "Which component is responsible for translating virtual addresses to physical addresses?",
          "options": [
            "Page Table",
            "Instruction Register",
            "Cache Controller",
            "Disk Scheduler"
          ],
          "correctAnswer": "Page Table"
        },
        {
          "question": "What event occurs when an accessed page is not present in RAM?",
          "options": [
            "Segmentation Fault",
            "Page Fault",
            "Stack Overflow",
            "Deadlock"
          ],
          "correctAnswer": "Page Fault"
        },
        {
          "question": "Paging eliminates the requirement for which of the following?",
          "options": [
            "Contiguous allocation of physical memory",
            "Virtual address spaces",
            "RAM blocks",
            "CPU instruction cycles"
          ],
          "correctAnswer": "Contiguous allocation of physical memory"
        }
      ]
    }
  }
  ```

- **Error Responses**:

  - **`400 Bad Request`** (Validation failure):
    ```json
    {
      "success": false,
      "error": "Please provide notes with at least 20 characters."
    }
    ```

  - **`500 Internal Server Error`** (LLM Failure / Parsing issue):
    ```json
    {
      "success": false,
      "error": "Failed to generate revision resources. The AI model returned an unexpected format. Please try again."
    }
    ```

### 2.3 Save Revision Session *(Optional / Stretch)*

#### `POST /sessions`
Saves a student's completed session along with their quiz score to the MongoDB database.

- **Request Body**:
  ```json
  {
    "rawNotes": "Operating Systems lecture: Paging...",
    "summary": "Paging is a memory management technique...",
    "flashcards": [...],
    "quiz": [...],
    "score": 100,
    "totalQuestions": 3
  }
  ```

- **Success Response** (`201 Created`):
  ```json
  {
    "success": true,
    "sessionId": "66df21a4bc56789a12345678",
    "message": "Session saved successfully."
  }
  ```

---

### 2.4 Get Session History *(Optional / Stretch)*

#### `GET /sessions`
Retrieves a list of recent revision sessions.

- **Success Response** (`200 OK`):
  ```json
  {
    "success": true,
    "sessions": [
      {
        "_id": "66df21a4bc56789a12345678",
        "createdAt": "2026-09-10T05:15:00.000Z",
        "summary": "Paging is a memory management technique...",
        "flashcardCount": 3,
        "quizCount": 3,
        "score": 100
      }
    ]
  }
  ```
